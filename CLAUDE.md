# Working rules for this repository (set by Omri Gitter, 2026-11-02)

These rules override default behaviour. Read them before any change.

1. Every message from Omri is a numbered checklist. Before building, reply with the same numbers and a one-line reading of each item. Build only after he says go, unless he has said to skip the check.
2. After building, audit every item against his exact wording and report per item: DONE, NOT DONE, or ASSUMED (with the assumption in one line). Never report the whole task as done when any item is not.
3. Never reuse an asset, layout or wording he has rejected. If the asked-for replacement does not exist, say so in one line and stop on that item; do not substitute.
4. No invented copy. Use only wording he supplied, wording on longevitylifeacademy.com, or wording in the approved promo text. Mark any sentence you wrote yourself as UNAPPROVED in the report.
5. No font, colour, logo or layout changes beyond the exact ask. Copy the production design; do not design.
6. Verify on the real page the user sees (the deployed URL), not only a local render. If the real page cannot be reached, say VERIFIED LOCALLY ONLY.
7. Never write "nothing is pending". Always list open items against his original asks. Do not repeat a known blocker (such as a blocked push) unless he asks.
8. Never touch tracking scripts (Meta CAPI, GA). Never submit the checkout or enrol forms. Never spend paid credits without his explicit word.
9. If an instruction can be read two ways, write the reading you chose in one line before acting.
